## SYNC #0092 — WEB → APP
**2026-10-03 15:30**

### Cel tego sync: czy APP musi coś zmienić po moich dzisiejszych zmianach w `onEventUpdated`?

Krótka odpowiedź: **kod wysyłający powiadomienia to wyłącznie Cloud Function
(`functions/index.js`, backend, wspólny dla WEB i APP)** — nie zmieniałem
niczego w kliencie mobilnym. Więc APP **nie musi** nic zmieniać, żeby
powiadomienia zaczęły latać poprawnie — to się dzieje automatycznie po
stronie serwera, niezależnie czy edycja/usunięcie wyszło z WEB czy z mobile.

**Ale** — jeśli APP renderuje listę powiadomień (np. ikona/kolor/etykieta na
podstawie pola `type`), poniżej jest lista NOWYCH wartości `type`, które
mogą się teraz pojawić w kolekcji `notifications`. Jeśli u Was gdzieś jest
switch/mapa po `type` z fallbackiem "nieznany typ" — te trzy warto dopisać.

---

### 1. Nowy typ: `TASK_DELETED` (zadania, #0086)
Wysyłane gdy trener usuwa zadanie. `title`: "Zadanie usunięte".

### 2. Nowy typ: `EVENT_DELETED` (eventy, #0088)
Wysyłane gdy trener usuwa event (`status: 'DELETE'`). `title` z 4 wariantami
wg typu eventu: "Usunięty trening" / "Usunięty mecz" / "Usunięty wyjazd" /
"Usunięte wydarzenie" (EN: Deleted training/match/trip/event).

### 3. `EVENT_UPDATED` — rozszerzony zakres wyzwalaczy (#0091)
Typ już istniał, ale TERAZ dodatkowo wysyła się przy:
- zmianie **tylko** tytułu lub opisu eventu (wcześniej nie wysyłał),
- dopisaniu **nowego zawodnika/trenera** do eventu przy edycji, nawet jeśli
  to jedyna zmiana (wcześniej to był bug — guard blokował tę ścieżkę).

Treść `body` może teraz zawierać nowe frazy: "📝 Tytuł: ..." / "📝 Zmieniono
opis" (EN: "📝 Title: ..." / "📝 Description changed") — to są kolejne
elementy tej samej listy `changes`, którą pewnie już parsujecie/wyświetlacie
razem z "📅 Data: ..." itp.

---

### Skąd to się wzięło (dla kontekstu)

Dziś wdrożyłem na WEB realną edycję eventu (wcześniej był tam placeholder
"Edycja — wkrótce", patrz #0090). Przy testach Rafał zauważył, że edycja nie
wysyła push w ogóle albo nie wysyła go nowo dopisanemu zawodnikowi — stąd
poprawki #1091 w `onEventUpdated`. Jeśli u Was w mobile jest analogiczna
funkcja edycji eventu (albo będzie), to po stronie backendu już działa
poprawnie — nie trzeba nic dublować.
