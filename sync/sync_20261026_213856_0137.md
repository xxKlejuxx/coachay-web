# Sync #0137 — WEB → MOBILE (2026-10-26)

## Bug: liczniki obecności na meczu pokazują tylko potwierdzonych, pomijają długie nieobecności

Rafał zgłosił, że na ekranie Start (karta najbliższego/aktualnego meczu) liczniki
Obecni/Nieobecni/Brak odp. pokazywały **0/0/0** dla meczu, mimo że szczegółowy widok
kalendarza (dzień → lista eventów) poprawnie pokazywał "2 potwierdziło, 1 ma długą
nieobecność". Po stronie APP zgłoszono analogiczny, pokrewny problem: **pokazujecie
tylko tych, którzy jawnie potwierdzili (`confirmed`), a nie pokazujecie wcale osób
z długoterminową nieobecnością** (kolekcja `absences`) jako "nieobecny".

### Przyczyna #1 (główna, web): sentinel `'__TEAM__'` nie był rozwijany

Gdy event zaprasza całą drużynę, `matchData`/`attendance.invited` NIE zawiera listy
ID zawodników — zawiera jeden string-sentinel `'__TEAM__'`. Część ekranów (dzień
w kalendarzu) już to poprawnie rozwijała do pełnego aktywnego składu drużyny, ale
karta meczu na Start tego nie robiła:

```js
// ŹLE (stare, zawsze dawało invP = [] gdy invited = ['__TEAM__']):
const invP = (att.invited || []).filter(id => id.includes('player_'));

// DOBRZE:
const invP = (att.invited || []).includes('__TEAM__')
    ? teamPlayers.map(p => p.playerId)   // pełny aktywny skład drużyny
    : (att.invited || []).filter(id => id.includes('player_'));
```

**Sprawdźcie, czy wasz kod obsługujący `attendance.invited` wszędzie rozpoznaje
`'__TEAM__'`** i rozwija go do pełnej listy aktywnych zawodników drużyny (nie tylko
tam, gdzie akurat to przetestowaliście) — to jest dokładnie ten sam bug, tylko
w innym miejscu ekranu.

### Przyczyna #2 (zgłoszona przez was): długie nieobecności w ogóle nie są liczone

Kolekcja `absences` (długoterminowe nieobecności zawodnika, np. kontuzja/wyjazd na
dłużej) musi być **sprawdzana osobno** — to NIE jest to samo co `attendance.declined`
/`attendance.markedAbsent` (te powstają z akcji na konkretnym evencie). Schemat
dokumentu `absences/{id}`:

```
{ playerId, teamId, dateFrom: 'YYYY-MM-DD', dateTo: 'YYYY-MM-DD', isActive: true, ... }
```

Zapytanie (u nas, 1:1 z appką wg sync #0041):

```js
async function getTeamAbsences(teamId) {
    try {
        const snap = await db.collection('absences')
            .where('teamId', '==', teamId)
            .where('isActive', '==', true)
            .get();
        return snap.docs.map(d => d.data());
    } catch (e) {
        console.error('❌ getTeamAbsences', e);
        return [];
    }
}

// Aktywna nieobecność zawodnika pokrywająca datę meczu:
function findAbsenceFor(playerId, dateStr, absencesList) {
    if (!playerId || !dateStr) return null;
    return absencesList.find(a =>
        a.playerId === playerId && a.dateFrom <= dateStr && a.dateTo >= dateStr
    ) || null;
}
```

Pełna logika liczenia (u nas w `renderMatchCard`, priorytet: **confirmed bije
wszystko inne** — jeśli ktoś mimo nieobecności ręcznie potwierdził obecność,
liczy się jako obecny):

```js
const invP = (att.invited || []).includes('__TEAM__')
    ? teamPlayers.map(p => p.playerId)
    : (att.invited || []).filter(id => id.includes('player_'));

const confSet = new Set(att.confirmed || []);
const conf = invP.filter(id => confSet.has(id)).length;

// Nieobecny = declined LUB markedAbsent LUB (długa nieobecność pokrywająca datę meczu)
// — ale TYLKO jeśli nie ma w confirmed (priorytet PO confirmed).
const decl = invP.filter(id =>
    !confSet.has(id) && (
        (att.declined || []).includes(id) ||
        (att.markedAbsent || []).includes(id) ||
        findAbsenceFor(id, match.date, teamAbsences)
    )
).length;

const noResp = Math.max(0, invP.length - conf - decl);
```

### Przyczyna #3 (race warunków ładowania, web-specific, ale sprawdźcie analogicznie u siebie)

Lista zawodników drużyny i lista nieobecności ładowały się u nas w osobnej funkcji
od tej, która renderuje kartę meczu na Start — przez co przy pierwszym wejściu na
ekran karta renderowała się zanim te dane w ogóle zdążyły dotrzeć, więc liczniki
bywały złe nawet po naprawieniu punktu 1 i 2. Rozwiązanie: funkcja ładująca kartę
meczu pobiera **własną, niezależną kopię** zawodników drużyny i aktywnych
nieobecności (nie czeka na inny, równoległy loader) i dopiero wtedy liczy/renderuje.
Jeśli u was też jest osobny "dashboard/home" loader niezależny od loadera
kalendarza/szczegółów meczu — upewnijcie się, że oba mają dostęp do tych samych,
już załadowanych danych zanim policzą liczniki.
