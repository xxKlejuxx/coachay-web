# Sync #0101 — MOBILE → WEB (2026-10-06)

Decyzja Rafała: **usuwamy demo ZAWODNIK (`demo_zawodnik_jasiek`) i KIBIC (`demo_obserwator_babcia`)**
oraz sprzątamy konta anonimowe w Firebase Authentication. Kluby (w tym `club_orly_praga`) NIE są ruszane.
Zostają demo na kontach email: `demo_trener_jan` i `demo_rodzic_anna` (prawdopodobnie używane przez Apple review —
nie ruszać).

## Co zrobił mobile (v1.1.24)

Usunięta ścieżka `signInAnonymously` + `setDemoRole` z `doLoginDemo` (login.tsx) oraz wpisy ZAWODNIK/KIBIC z
`DEMO_USER_MAP`. Appka nie tworzy już kont anonimowych. (Przyciski tych dwóch demo były już wcześniej ukryte.)

## Prośby do WEB

1. **Sprawdzić/skasować w Firestore** dokumenty demo, jeśli WEB też ich nie używa: `users/demo_zawodnik_jasiek`,
   `users/demo_obserwator_babcia` (oraz ich powiązane memberships/players, jeśli są osobne i wyłącznie demo).
   `demo_trener_asystent` — nie znalazłem go w kodzie mobile, Rafał go wymienił jako testowego usera w `club_orly_praga`;
   WEB niech zdecyduje czy używa (Rafał: kluby nie są ruszane, więc najpewniej zostaje).
   Mobile NIE kasuje nic w Firestore (bez Admin SDK).
2. **Zamknięcie dziury w regułach.** `inMyClub()` ma `isAnonymous() ||` — każde konto anonimowe czyta dane
   WSZYSTKICH klubów. Po usunięciu demo Jasiek/Babcia (które na tym działały) można: usunąć `isAnonymous()` z reguł
   (`inMyClub`) i wyłączyć providera **Anonymous** w Firebase Authentication. Prosimy o potwierdzenie, że WEB
   nie używa już anonimowego logowania (np. demo web), zanim to zrobicie.
3. **Sprzątanie kont anonimowych w Authentication** (hurtowo, np. jednorazowa Cloud Function wywoływana przez admina
   platformy lub skrypt Admin SDK po stronie WEB). Rafał policzył konta z konsoli (350 łącznie, większość anonimowych).
   Konta demo mailowe (`klejux+demo_trener@…`, `klejux+demo_parents@…`) i konta realnych userów NIE kasować.
   Osierocone `authIndex/{uid}` kont anonimowych można usunąć razem z nimi. Przed kasowaniem — eksport Firestore.
4. Opcjonalnie pole `isTest` na klubie jako znacznik danych testowych na przyszłość.

## Uwaga

`DEMO_PASSWORD` jest wpisane w kodzie appki (stałe hasło kont demo trener/rodzic) — przy publicznych buildach każdy może
je odczytać. Skoro to konta demo, ryzyko małe, ale warto, żeby konta demo miały minimalne uprawnienia (nic płatnego/wrażliwego).
