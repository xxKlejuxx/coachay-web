# SYNC #0174 — WEB → APP
Data: 2026-11-07

## 1) BUG: niespójność "cofnij zakończenie meczu" między ekranem Start a ekranem Mecz (appka mobilna)

Zgłoszenie od Rafała: na telefonie mecz **"Rocznik 2012 vs Bks"** (event
`event_20261107_7051542418`, teamId `team_20260401_7035579`) był LIVE,
został zakończony, a następnie **przywrócony ("cofnij zakończenie")** —
ale po przywróceniu appka pokazywała mecz jako NIE zakończony (LIVE)
tylko z ekranu jednego miejsca, a z drugiego (czy na www, po hard
refresh) wciąż jako FINISHED.

Sprawdziliśmy bezpośrednio w Firestore (odczyt na żywo, nie cache):

```
matchStatus: FINISHED
endedAt:     2026-11-06T23:52:56.783Z
endedBy:     user_TRENER_GLOWNY_20260401_9212228
result:      3:2 (WIN)
clockSegments: [{ start: 2026-11-06T23:52:46.437Z, end: 2026-11-06T23:52:56.783Z }]
updateTime (ostatni zapis do dokumentu): 2026-11-07T14:50:26.856Z
```

Ten ostatni zapis (14:50:26) to **nasz cron `sendEventReminders`**
(pole `reminderSentAt`) — **nie istnieje żaden zapis późniejszy niż
zakończenie meczu**, który świadczyłby o udanym "cofnięciu
zakończenia". Czyli: web pokazywał to, co faktycznie jest w bazie
(FINISHED) — **nie jest to problem cache/www**.

Wniosek Rafała, z którym się zgadzamy: w appce mobilnej akcja
"cofnij zakończenie" wywołana z **ekranu Start** zachowuje się inaczej
niż ta sama akcja wywołana z **ekranu Mecz** — jedna z nich (prawdopodobnie
ta z ekranu Start) nie zapisuje zmiany do Firestore (albo robi to
tylko lokalnie/optymistycznie w UI), podczas gdy druga faktycznie
pisze do bazy. Prośba do APP: sprawdzić, czy obie ścieżki
"cofnij zakończenie" wołają tę samą funkcję zapisu do
`matchData.matchStatus`/`endedAt`/`endedBy`/`clockSegments`, czy to
dwie osobne implementacje, które się rozjechały.

(Przy tej okazji, do wiadomości: WEB — po stronie `start.html` —
`mpReopenMatch` i nowy `lcpEnd`/`lcpStart` zarządzają `clockSegments`
konsekwentnie, patrz sync #0173.)

## 2) Temat do ustalenia: treść push "przypomnienie o evencie" (EVENT_REMINDER)

Tak jak wcześniej `MATCH_FINISHED` (sync #0172 — ustaliliśmy wspólnie
tytuł "Koniec meczu" + treść "{event.title}: nasz:przeciwnik" i push
stał się widoczny), **`EVENT_REMINDER` jest nadal cichy/bez treści**:

```js
// functions/index.js, sendDirectPush()
{
  to: expoToken,
  sound: null,
  _contentAvailable: true,
  data: { type: 'EVENT_REMINDER', referenceId: eventId }
}
```

Appka mobilna sama dociąga event po `referenceId` i buduje lokalne
powiadomienie (tytuł/treść po stronie klienta). Rafał poprosił, żeby
ten temat też zapisać i ustalić wspólnie z APP, co ma pójść w tytule
i treści, zanim ewentualnie zrobimy to samo co z MATCH_FINISHED
(widoczny push budowany po stronie backendu, żeby tekst był identyczny
na obu platformach i niezależny od lokalnej logiki appki).

Propozycja do rozważenia (do decyzji, nie wdrożone):
- Tytuł: nazwa typu wydarzenia (np. "Przypomnienie: mecz" / "Przypomnienie: trening")
- Treść: `{event.title}` + godzina startu (`timeFrom`)

Czekamy na input od APP / decyzję Rafała, zanim to zakodujemy.
