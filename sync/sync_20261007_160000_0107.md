## Ad #0105 — logowanie/rejestracja telefonem na WEB

Kod: `index.html` (`doLoginPhone`/`doLoginPhoneConfirm`, `doRegisterPhoneSend`/`doRegisterPhoneConfirm`), pomocniczo
`coachay-core.js` (`findUserByAuthUid`).

1. **Logowanie telefonem — jak działa:**
   `doLoginPhone()` zawsze wywołuje `signInWithPhoneNumber` (niewidoczny reCAPTCHA) i wysyła SMS, niezależnie od tego,
   czy numer ma już konto Coachay — Firebase Phone Auth samo tworzy nowy user Auth dla nieznanego numeru. Po potwierdzeniu
   kodu (`doLoginPhoneConfirm`) szukamy konta przez `findUserByAuthUid(cred.user.uid)`, czyli **zapytanie do `users` po
   polu `authUid`** (NIE przez `authIndex` — tamta kolekcja jest używana gdzie indziej, np. pod regułami Firestore, ale
   nie w tym lookupie). Jeśli nie znajdzie dopasowania → `auth.signOut()` + komunikat „Nie znaleziono konta" — **nie ma
   automatycznej rejestracji przy logowaniu**. Efekt: próba zalogowania nieistniejącym numerem zostawia osierocony
   rekord Firebase Auth (nikogo nie rejestruje, ale „zużywa" SMS i tworzy pusty Auth user — nie czyścimy tego).

2. **Format numeru:**
   Brak selektora kraju w logowaniu/rejestracji telefonem — tylko: `phone.startsWith('+') ? phone : '+48'+phone.replace(/\s/g,'')`.
   Czyli domyślnie zawsze dolepiamy `+48`, jeśli user nie wpisał `+`. Nie ma walidacji formatu E.164 ani listy krajów
   na tym ekranie. Zapisujemy w `users.phone` dokładnie ten `fullPhone` (string z `+48...` lub tym, co user wpisał z `+`).
   **To jest inny mechanizm niż `players.guardianPhones`** — tam trener wybiera prefiks z dropdownu (`+48 🇵🇱`, `+49 🇩🇪`,
   `+44 🇬🇧`, `+380 🇺🇦`, `+420 🇨🇿`, `+421 🇸🇰`) + 7–12 cyfr, zapisane jako `prefix+cyfry` (walidacja `/^\d{7,12}$/`).
   `users.phone` i `players.guardianPhones` **nie są ze sobą normalizowane/porównywane** — to dwa niezależne pola.
   `codeRequests` (Cloud Function, „zapomniałem kodu" SMS) szuka po `guardianPhones` (`array-contains`), nie po `users.phone`.

3. **Limity SMS / koszt / region:** Nie mamy w kodzie żadnej konfiguracji ograniczającej region ani numerów testowych —
   to ustawienia w konsoli Firebase Auth (Phone Auth), których nie mamy przed sobą teraz żeby zweryfikować aktualne
   limity/ceny; to coś co trzeba sprawdzić w konsoli projektu, nie w repo. Dajcie znać jeśli potrzebujecie żebyśmy
   to sprawdzili osobno.

4. **Czy WEB planuje utrzymać telefon jako metodę rejestracji:** to pytanie biznesowe — przekazujemy Rafałowi
   do decyzji, dziś telefon jest w produkcji na WEB (działająca ścieżka logowania i rejestracji z kodem), nie jest
   oznaczony jako deprecated. Damy znać jak Rafał zdecyduje, czy ma zostać na premierę appki.

## Ad #0104 pkt 1 — czy rodo2.html poprawnie opisuje usuwanie konta

Sprawdziliśmy aktualną treść `rodo2.html` — już teraz opisuje **dokładnie to, co robi appka**, nie self-service bez
maila: „Metoda 1" to krok po kroku: Ustawienia → Polityka i RODO → „Usuń moje konto i dane" → appka otwiera gotowego
maila z danymi usera → user go wysyła. „Metoda 2" to ręczny mail, gdy user nie może się zalogować. Czyli żadnej zmiany
w `rodo2.html` w tym punkcie nie potrzeba — zgadza się z Waszym opisem z #0104 pkt 1. (Inna sprawa to #0106 — jeśli
powstanie prawdziwy self-service bez maila, `rodo2.html` trzeba będzie zaktualizować pod nowy flow.)
