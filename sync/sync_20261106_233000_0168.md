# Sync #0168 — MOBILE → WEB (2026-11-06)

Dotyczy pkt 2 z #0167. Rafał zdecydował: **jedna konwencja, WEB i APP mówią jednym językiem.**

## Konwencja: pola `status` zawsze WIELKIMI LITERAMI

Proponowana i przyjęta po stronie mobile: `ACTIVE`, `GRACE`, `DEMO`, `DELETE`, `PENDING`, `DONE`, `TRIAL`, `EXPIRED`, `BLOCKED`, `UPCOMING`, `LIVE`, `FINISHED` — spójnie z tym, co już jest wielkimi literami (DELETE, PENDING, DONE, matchStatus, licenseStatus).

Dlaczego wielkie: większość pól statusu w obu systemach już jest wielkimi literami; `memberships.status` to jedyne istotne odstępstwo (WEB pisze `active`).

## Co robi MOBILE (zrobione)

- Wszystkie zapisy `memberships.status` w appce piszą `ACTIVE` (ostatni wyjątek: `login.tsx` zakładanie głównego trenera pisało `active` — poprawione).
- Odczyty zostają na razie tolerancyjne (`in ['active','ACTIVE', ...]`) do czasu migracji danych przez WEB. Po potwierdzeniu migracji zwężę do `== 'ACTIVE'` w osobnym syncu (nie wcześniej — inaczej zniknęłyby członkowie).

## Co ma zrobić WEB

1. **Kod:** wszystkie nowe zapisy `status` (memberships i inne kolekcje: Cloud Functions, panel www, rejestracja, dołączanie kodem, import) → wielkimi literami. Zrób grep po `status: 'active'` / `'grace'` / `'demo'` / `"active"` itp. w WEB i w `functions/`.
2. **Odczyty w WEB/CF:** porównania `status === 'active'` zamień na tolerancyjne na czas migracji (`String(status).toUpperCase() === 'ACTIVE'`) lub od razu na `'ACTIVE'` po migracji danych.
3. **Migracja danych (jednorazowy skrypt):** w `memberships` zamień `active→ACTIVE`, `grace→GRACE`, `demo→DEMO` (i inne warianty wielkości liter), uzupełnij brakujące `status` (`ACTIVE`). Najpierw dry-run: rozkład wartości + lista ID do zmiany; wykonaj po akceptacji Rafała.
4. **Triggery CF:** uważaj, żeby masowy update `status` nie odpalił `onMembershipUpdated` (naliczanie `usedSlot`, pushe). Jeśli odpali — zablokuj/obejdź na czas migracji (np. flaga) albo zweryfikuj, że przy samej zmianie wielkości liter funkcja nic nie robi.
5. **Reguły Firestore** (`firestore.rules`): sprawdź porównania z `'active'`/`'ACTIVE'` — ujednolić, żeby migracja nie odcięła dostępu.
6. Odpisz: kiedy migracja wykonana + liczba zmienionych dokumentów. Wtedy mobile zawęża zapytania do jednego `==`.
