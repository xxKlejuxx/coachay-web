## 1. Licznik (zielony/czerwony/szary) — `countAttendance()`

```ts
// src/lib/calendar.ts
export function countAttendance(ev: CoachayEvent, players: Player[], absences: Absence[]): { green: number; red: number; grey: number; total: number } {
  const att = (ev as any).attendance || {};
  const invited: string[] = att.invited || [];
  const confirmed: string[] = att.confirmed || [];
  const declined: string[] = att.declined || [];
  const markedAbsent: string[] = att.markedAbsent || [];
  const eventDate = ev.date;

  const playerIds = invited.includes('__TEAM__')
    ? players.map((p) => p.playerId || p.id)
    : invited.filter((id) => id.includes('player_'));

  let green = 0, red = 0, grey = 0;
  playerIds.forEach((id) => {
    const hasAbsence = absences.some((a) => a.playerId === id && a.dateFrom <= eventDate && a.dateTo >= eventDate && a.isActive);
    if (confirmed.includes(id)) green++;
    else if (declined.includes(id) || markedAbsent.includes(id) || hasAbsence) red++;
    else grey++;
  });
  return { green, red, grey, total: playerIds.length };
}
```

Kluczowa linia: `hasAbsence` — sprawdza, czy KTÓRAŚ z aktywnych nieobecności zawodnika obejmuje datę TEGO KONKRETNEGO eventu (`a.dateFrom <= eventDate && a.dateTo >= eventDate`). Jeśli tak, liczy się jako czerwony (nieobecny), tak samo jak `declined`/`markedAbsent` — nieobecność z długiego zwolnienia ma ten sam wpływ na licznik co ręczne odrzucenie.

## 2. Status + przyczyna per osoba w szczegółach eventu — `buildAttendanceRows()`

```ts
// src/lib/calendar.ts
const getAbsence = (personId: string) =>
  absences.find((a) => a.playerId === personId && a.dateFrom <= eventDate && a.dateTo >= eventDate && a.isActive);

// ...dla każdej osoby na liście (filteredInvited.forEach):
const absence = getAbsence(personId);
let status: 'present' | 'absent' | 'pending';
let statusText: string;
let reasonText: string | undefined;
if (absence) {
  status = 'absent';
  statusText = i18n.t('kalendarz.attStatusAbsentLocked'); // np. "Nieobecność (zwolnienie)"
  const endDate = new Date(absence.dateTo + 'T00:00:00').toLocaleDateString(localeOf(), { day: 'numeric', month: 'short' });
  reasonText = i18n.t('kalendarz.absenceReasonUntil', { reason: absence.reason, date: endDate }); // np. "Złamanie nogi (do 31 gru)"
} else if (confirmed.includes(personId)) {
  status = 'present'; statusText = i18n.t('kalendarz.attStatusPresent');
} else if (declined.includes(personId)) {
  status = 'absent'; statusText = i18n.t('kalendarz.attStatusAbsent');
  if (reasons[personId]) reasonText = i18n.t('kalendarz.declineReasonQuoted', { reason: reasons[personId] });
} else if (markedAbsent.includes(personId)) {
  status = 'absent'; statusText = i18n.t('kalendarz.attStatusAbsentByCoach');
} else {
  status = 'pending'; statusText = i18n.t('kalendarz.attStatusPending');
}
```

`absence` sprawdzane jest jako PIERWSZE, przed `confirmed`/`declined`/`markedAbsent` — długa nieobecność ma priorytet nad każdym innym stanem (nawet gdyby ktoś wcześniej ręcznie potwierdził obecność, nieobecność z `absences` i tak pokaże się jako "absent" z przyczyną i datą końcową).

## Podsumowanie dla Waszej implementacji

- Zapytanie: `absences where teamId==X and isActive==true` (całość dla drużyny, nie per event) — filtr po dacie robicie Wy, przy renderowaniu, per event.
- Sprawdzenie: `dateFrom <= eventDate && dateTo >= eventDate` — to jest to samo, co już macie w `countAttendance`-odpowiedniku (jeśli w ogóle go wołacie z `absences` — jak pisaliście w #0035, dziś NIE wołacie, więc to jest właśnie brakujący element).
- Priorytet: `absence` sprawdzane PRZED `confirmed`/`declined`/`markedAbsent`.
- UI: nieobecność = zablokowana edycja (brak przycisków), status + przyczyna + data końca widoczne.
