## SYNC #0088 — WEB → APP
**2026-10-03 13:00**

### Temat: usunięcie eventu teraz wysyła powiadomienie (EVENT_DELETED)

Nawiązując do mojego poprzedniego sync (#0087 / wcześniej #0086): potwierdziłem
tam, że usunięcie eventu (`status: 'DELETE'`) nie wysyłało ŻADNEGO powiadomienia
— `onEventUpdated` w branchu B sprawdza tylko zmiany `date`/`timeFrom`/`timeTo`/
`location.venueName`, a przy samym przełączeniu statusu na DELETE te pola się
nie zmieniają, więc funkcja wychodziła bez wysyłki.

Rafał zaproponował hack (zmienić np. godzinę o sekundę żeby "oszukać" branch B),
ale to wysyłałoby ZŁĄ treść powiadomienia (`EVENT_UPDATED` / "zmieniono godzinę"
dla eventu który w ogóle nie istnieje). Zamiast tego dodaliśmy właściwą obsługę.

### Co zmieniono (`functions/index.js`, `onEventUpdated`)

Nowy branch **A2** (między CANCELLED i zmianą daty/godziny/miejsca):

```js
// ── A2: Usunięcie eventu ─────────────────────────────────────────
if (before.status !== 'DELETE' && after.status === 'DELETE') {
    try {
        const oldSnap = await db.collection('notifications')
            .where('referenceId', '==', eventId)
            .where('actionDone', '==', false)
            .get();
        const batch = db.batch();
        oldSnap.forEach(doc => {
            batch.update(doc.ref, { actionDone: true, actionResult: 'expired', isRead: true, readAt: new Date().toISOString() });
        });
        if (!oldSnap.empty) await batch.commit();
    } catch (e) { console.warn('onEventUpdated DELETE — dezaktywacja notif:', e); }

    const recipients = await resolveInvitedUserIds(after, after.deletedBy || after.createdBy);
    let sent = 0;
    for (const { userId, forPlayerId, playerName } of recipients) {
        await createNotification({
            userId, teamId: after.teamId,
            type: 'EVENT_DELETED',
            title: i18n.deletedTitle(after.type),
            body: buildNotifBody(after, { childName: playerName || null }),
            referenceId: eventId, referenceType: 'event',
            forPlayerId: forPlayerId || null, requiresAction: false,
        });
        sent++;
    }
    return;
}
```

Działa analogicznie do istniejącego branchu A (CANCELLED): dezaktywuje stare
powiadomienia ATTENDANCE/CREATED, wysyła nowy typ **`EVENT_DELETED`** do
wszystkich zaproszonych (`resolveInvitedUserIds`), z tytułem z nowego
`i18n.deletedTitle(type)` ("Usunięty trening" / "Usunięty mecz" / "Usunięty
wyjazd" / "Usunięte wydarzenie" — i wersje EN).

### Co jeszcze doszło

- `coachay-core.js`: nowy wpis `EVENT_DELETED: '#EF4444'` w `notifBorderColors`
  (ten sam czerwony co `EVENT_CANCELLED` — lewy border na karcie powiadomienia).
- Cache-bust: `coachay-core.js?v=20261003b` we wszystkich plikach HTML (bo
  zmienił się wspólny plik).

### Dla APP

Jeśli u Was powiadomienia o eventach renderujecie wg `type` (kolor/ikona/
etykieta), warto dodać `EVENT_DELETED` analogicznie do `EVENT_CANCELLED` —
inaczej dostaniecie nieznany typ bez stylu. `body` jest budowane tym samym
`buildNotifBody()` co przy CANCELLED (typ + data + godzina + miejsce), bez
pola `changes`.

Wdrożone: `firebase deploy --only functions:onEventUpdated` + hosting,
commit `0b04f1a` na `main`.
