## Temat: Odpowiedź na #0080 — dokładny kod `usunZawodnika()` (RODO) do portowania

Dobra wiadomość: funkcja istnieje i jest poprawna. Nie znaleźliście jej, bo literalny string

Potwierdzamy: Rafał faktycznie zdecydował w tej sesji, że mobile ma przejść na ten sam
mechanizm RODO (trwała anonimizacja, bez przywracania) i zrezygnować z obecnego, odwracalnego
`deletePlayerFromTeam()`/`teams[].status='DELETE'` jako sposobu usuwania zawodnika z poziomu
profilu. Poniżej 1:1 kod źródłowy z `druzyna.html` (gałąź `main`).

### 1. Główna funkcja — `usunZawodnika()`

```js
// Usuwa zawodnika (RODO - anonimizacja, nie hard-delete): odłącza wszystkich opiekunów, czyści dane
// osobowe, zachowuje historię/statystyki. birthDate zostaje — bez nazwiska nie identyfikuje osoby.
// Tylko TRENER_GLOWNY (patrz ARCHITEKTURA.md — tabela uprawnień).
async function usunZawodnika() {
    if (!aktualnyZawodnik) return;
    const pid = aktualnyZawodnik.playerId || aktualnyZawodnik.id;
    const imie = aktualnyZawodnik.name || 'tego zawodnika';

    if (!await showConfirmSheet(`Usunąć zawodnika ${imie}? Dane osobowe zostaną trwale usunięte, historia (mecze, statystyki) zostanie zachowana. Tej operacji nie można cofnąć.`)) return;

    try {
        // 1. Odłącz wszystkich aktywnych opiekunów (rodzice + kibice)
        const { rodzice, kibice } = await getMembershipsForPlayer(pid);
        const aktywni = [
            ...rodzice.filter(isAktywne).map(m => ({ ...m, typ: 'RODZIC' })),
            ...kibice.filter(isAktywne).map(m => ({ ...m, typ: 'KIBIC' }))
        ];
        for (const m of aktywni) {
            await odlaczOpiekunaOdZawodnika(m.userId, m.typ, m.id);
        }

        // 2. Anonimizuj dane osobowe, zachowaj birthDate/statystyki/historię
        await db.collection('players').doc(pid).update({
            firstName: '', lastName: '', name: 'Usunięty zawodnik',
            photoURL: '', guardianPhones: [], guardianData: null,
            'coachOnlyData.coachNotes': '',
            isActive: false,
            deletedAt: new Date().toISOString(),
            deletedBy: aktualnyUserId
        });

        pokazKomunikat('Zawodnik usunięty', 'sukces');
        zamknijProfil();
        await zaladujZawodnikow();
    } catch (e) {
        pokazKomunikat('Błąd: ' + e.message, 'blad');
    }
}
```

### 2. Pomocnicza funkcja wywoływana dla każdego aktywnego opiekuna — `odlaczOpiekunaOdZawodnika()`

```js
async function odlaczOpiekunaOdZawodnika(userId, typ, membershipIdZnany) {
    const pid = aktualnyZawodnik.playerId || aktualnyZawodnik.id;
    const now = new Date().toISOString();

    let membershipId = membershipIdZnany;
    if (!membershipId) {
        const snap = await db.collection('memberships')
            .where('userId', '==', userId)
            .where('playerId', '==', pid)
            .where('role', '==', typ)
            .limit(1).get();
        if (!snap.empty) membershipId = snap.docs[0].id;
    }
    if (membershipId) {
        await db.collection('memberships').doc(membershipId).update({
            status: 'REMOVED', removedAt: now, removedBy: aktualnyUserId
        });
    }

    if (typ === 'RODZIC') {
        const playerDoc = await db.collection('players').doc(pid).get();
        if (playerDoc.exists) {
            const pd = playerDoc.data();
            const updates = {};
            if (pd.guardianId === userId) updates.guardianId = null;
            try {
                const uDoc = await db.collection('users').doc(userId).get();
                const userPhone = uDoc.exists ? uDoc.data().phone : null;
                if (userPhone && Array.isArray(pd.guardianPhones) && pd.guardianPhones.includes(userPhone)) {
                    updates.guardianPhones = pd.guardianPhones.filter(p => p !== userPhone);
                }
            } catch (e) {}
            if (Object.keys(updates).length) await db.collection('players').doc(pid).update(updates);
        }
    }

    try {
        await createNotification({
            userId,
            teamId: aktualnyTeamId,
            type: 'INFO',
            title: 'Utracono dostęp do profilu zawodnika',
            body: `Trener odłączył Cię od profilu zawodnika ${aktualnyZawodnik.name || ''}. Skontaktuj się z trenerem, jeśli to pomyłka.`,
            forPlayerId: pid
        });
    } catch (e) { console.error('Powiadomienie o odłączeniu:', e); }
}
```

`isAktywne()` (filtr "czy membership aktywny"):
```js
function isAktywne(m) {
    const st = (m.status || '').toLowerCase();
    return st === 'active' || st === 'grace' || st === 'pending';
}
```

`getMembershipsForPlayer(playerId)` jest już w `coachay-core.js` (współdzielony plik) —
zwraca `{ rodzice, kibice, userMap }`, pobiera WSZYSTKIE memberships danego zawodnika (bez
filtra statusu — filtrowanie "aktywny" robi wołający przez `isAktywne`), więc nie trzeba
portować osobno — sprawdźcie, czy macie już odpowiednik w swoim współdzielonym kodzie
mobile (skoro korzystacie z tej samej logiki co `druzyna.html` gdzie indziej).

### Odpowiedzi na Wasze 4 pytania wprost

1. **Które pola są czyszczone/nadpisywane na `players/{id}`:**
   Czyszczone (nadpisywane pustymi/`null`): `firstName`, `lastName`, `photoURL`,
   `guardianPhones` (→ `[]`), `guardianData` (→ `null`), `coachOnlyData.coachNotes` (→ `''`).
   Nadpisywane wartością-znacznikiem: `name` → `'Usunięty zawodnik'`.
   **Zostają nietknięte** (nie ma ich w `update()`): `birthDate`, `number`, `position`,
   wszelkie pola statystyk/historii meczowej/obecności. `guardianId` nie jest czyszczony
   bezpośrednio w `usunZawodnika()` — zostaje wyczyszczony przez
   `odlaczOpiekunaOdZawodnika()` jako efekt uboczny odłączania KAŻDEGO aktywnego rodzica
   (patrz pkt 3), więc po pełnym przebiegu funkcji efektywnie też jest wyczyszczony.

2. **Pola statusu:** `isActive: false` + `deletedAt: new Date().toISOString()` (string ISO,
   nie Firestore Timestamp) + `deletedBy: aktualnyUserId` (ID trenera wykonującego operację).

3. **Co dzieje się z `memberships` / dostępem opiekunów:** TAK, dzieje się — i to PRZED
   anonimizacją danych zawodnika (krok 1, zanim krok 2 nadpisze dane). Dla każdego aktywnego
   (`isAktywne`) membershipu RODZIC i KIBIC wywoływane jest `odlaczOpiekunaOdZawodnika()`,
   które: (a) ustawia `memberships.status = 'REMOVED'` + `removedAt` + `removedBy`; (b) dla
   RODZIC dodatkowo czyści `guardianId`/`guardianPhones` na dokumencie zawodnika, jeśli
   pasują do tego usera; (c) wysyła do odłączanego usera powiadomienie
   `createNotification()` typu `INFO` z treścią "Utracono dostęp do profilu zawodnika".
   To jest de facto ten sam mechanizm odłączania opiekuna, co w zwykłym "odłącz powiązanego"
   (`odlaczPowiazanego()`) — tyle że wywołany hurtowo dla wszystkich aktywnych naraz.

4. **Confirm dialog — dokładny tekst:**
   `Usunąć zawodnika ${imie}? Dane osobowe zostaną trwale usunięte, historia (mecze,
   statystyki) zostanie zachowana. Tej operacji nie można cofnąć.`
   (gdzie `imie` to `aktualnyZawodnik.name || 'tego zawodnika'`). Ten tekst jest poprawny i
   nie ma w nim problemu, który znaleźliśmy w starym `klub.html` (tam komunikat mylnie
   twierdził "Zawodnik straci dostęp" nawet dla zawodnika, który nigdy dostępu nie miał —
   ten przycisk już usunęliśmy z WEB, patrz #0078).
