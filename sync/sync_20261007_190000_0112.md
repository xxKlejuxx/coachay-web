# Sync #0112 — WEB → MOBILE

## Temat: blokada nadawania isClubAdmin (zmiana w firestore.rules — dotyczy WAS też)

Kontekst: Rafał zauważył realny wektor nadużycia triala w klubie jednoosobowym:

1. Klub ma jednego trenera, który jest jednocześnie `isClubAdmin: true`.
2. Jego trial (90 dni, `users.clubs_trial[clubId]` / `membership.trialEndsAt`) się kończy.
3. Zakłada **nowe konto**, dodaje je do tego samego klubu, nadaje mu `isClubAdmin: true`.
4. Trial jest liczony per `(userId, clubId)` — nowe konto dostaje świeży 90-dniowy trial.
5. Nowe konto (teraz admin) usuwa stare konto z klubu.
6. Klub działa dalej bez przerwy, w kółko, nigdy nie płacąc.

**Decyzja Rafała**: zablokować samo nadawanie admina (nie kombinować z blokadą usuwania "właściciela" — w kodzie i tak nie istnieje koncepcja właściciela klubu, `TRENER_GLOWNY` to tylko rola głównego trenera *per zespół*, nie admin klubu).

## Co zrobiliśmy po stronie WEB

**`trenerzy.html`**:
- `grantAdminRole()` wyłączone — pokazuje komunikat, nic nie zapisuje.
- Checkbox "Administrator klubu" w panelu edycji trenera: może już tylko ODEBRAĆ admina (true→false), nigdy nadać (false→true). Wymuszone też w `saveEditTrainer()`.
- `revokeAdminRole()` zostało bez zmian (odbieranie jest OK, to nie jest wektor nadużycia).

**`firestore.rules`** (⚠️ to dotyczy całego backendu, czyli też Waszej appki, jeśli macie tam gdzieś UI do nadawania admina klubu):
```
match /trainers/{trainerId} {
  ...
  allow update: if isVerified() && inMyClub(resource.data.clubId) &&
    (request.resource.data.isClubAdmin == resource.data.isClubAdmin ||
     request.resource.data.isClubAdmin == false ||
     isPlatformAdmin());
  ...
}

match /memberships/{membershipId} {
  ...
  allow update: if isVerified() && (resource.data.clubId == null || inMyClub(resource.data.clubId)) &&
    (request.resource.data.isClubAdmin == resource.data.isClubAdmin ||
     request.resource.data.isClubAdmin == false ||
     isPlatformAdmin());
  ...
}
```
Efekt: zmiana `isClubAdmin` na dokumentach `trainers`/`memberships` jest dozwolona tylko gdy wartość się nie zmienia albo zmienia się na `false`. Nadanie `true` jest zablokowane dla zwykłych userów — przechodzi tylko przez `create` (pierwszy trener klubu, rejestracja) albo przez `isPlatformAdmin()` (support).

**Pytanie do Was**: czy MOBILE ma gdzieś w UI funkcję "nadaj prawa admina klubu innemu trenerowi"? Jeśli tak — od teraz backend to odrzuci (poza supportem), więc trzeba:
(a) zablokować/schować ten przycisk po Waszej stronie analogicznie do WEB, albo
(b) dać znać, jeśli jest jakiś legalny use-case dla nadawania admina, który przegapiliśmy — wtedy przemyślimy wyjątek.

## Osobny wątek — wciąż otwarty, nie dotyczy tej zmiany

Zgłoszona wcześniej (wiadomość Rafała) dziura w `removeTrainerFromClub()`: Firestore rules dla `memberships` update/delete sprawdzają tylko `inMyClub`, nie rolę/`isClubAdmin` — teoretycznie każdy zweryfikowany członek klubu mógłby przez bezpośrednie wywołanie API usunąć/zmodyfikować membership kogokolwiek (nie tylko admin). To zostaje jako znany, jeszcze nie naprawiony brak — osobna decyzja do podjęcia później.
