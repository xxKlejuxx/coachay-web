# Sync #0105 — MOBILE → WEB (2026-10-07 13:00)

## Rejestracja i logowanie telefonem (SMS) — prośba o wytyczne

Rafał pyta, czy rejestracja telefonem działa. Sprawdziliśmy kod:

- **WEB:** działa (Firebase Phone Auth: niewidoczny `RecaptchaVerifier` + `signInWithPhoneNumber`, opis w WEB #0072 C.1 krok 4b;
  zapis do Firestore od razu po potwierdzeniu SMS, przekierowanie na `start.html`).
- **MOBILE:** **NIE działa.** W `login.tsx` jest przycisk "Telefon" i pole numeru, ale akcja to tylko komunikat "wkrótce"
  (`comingSoon`). Nie ma `signInWithPhoneNumber` ani żadnego flow SMS. W `users` zapisujemy zawsze `phone: null`.

**Skutek:** konto założone telefonem na WEB nie może się zalogować w appce mobilnej (brak ścieżki logowania telefonem).
Dotyczy też usuwania konta w appce (ponowne potwierdzenie tożsamości przed `deleteUser` wymagałoby SMS).

## Prosimy WEB o wytyczne, zanim cokolwiek zbudujemy

1. Jak WEB obsługuje **logowanie** (nie tylko rejestrację) telefonem: ten sam numer → `findUserByAuthUid`? Co gdy numer nie ma konta?
2. Format numeru (E.164? domyślny prefiks +48? lista krajów?), co zapisujecie w `users.phone`, czy numer jest też w innych miejscach
   (np. `players.guardianPhones`, `codeRequests`) i jak się mają do `users.phone`.
3. Konfiguracja Firebase: limity SMS i koszt (Phone Auth jest płatny po limicie darmowym), czy są numery testowe, czy region SMS ograniczony.
4. Czy WEB planuje utrzymać telefon jako metodę rejestracji. Jeśli tak, mobile musi to zbudować (na RN Firebase JS SDK nie ma
   gotowego niewidocznego reCAPTCHA jak w przeglądarce — wymaga osobnego rozwiązania; to osobna, niemała praca po naszej stronie).
   Decyzja Rafała: czy telefon w appce w ogóle jest potrzebny na premierę.
