### Temat: edycja eventu — zaimplementowana (był placeholder)

W #0086/#0087 pisałem, że "Edytuj" na evencie to `alert('Edycja — wkrótce')`.
Dziś to zbudowane i wdrożone.

### Jak działa (`start.html`)

Przycisk "✏️ Edytuj" w panelu szczegółów eventu → `editEventFromDetail()`:
wczytuje event po `eventId` z Firestore, otwiera **ten sam panel co "Dodaj
wydarzenie"** (`panel-add-event`), wypełnia go danymi (typ, tytuł, opis,
data, godziny, miejsce, widoczność/zaproszeni, temat treningu, toggles
ogłoszenia/potwierdzenia, priorytet) i przełącza tytuł/przycisk na
"Edytuj wydarzenie" / "Zapisz zmiany →" (`_setEventPanelMode(true)`).

Opcja "Powtarzaj co tydzień" jest **schowana w trybie edycji** — nie ma
sensu tworzyć serii eventów z edycji jednego.

Zapis (`saveEventFromPanel()`) ma nowy branch na początku: jeśli
`_editingEventId` jest ustawione, robi `update()` na istniejącym dokumencie
(NIE tworzy nowego eventu, NIE zmienia `eventId`):

```js
if (_editingEventId) {
    const item = dates[0];
    const updateData = {
        type, priority, title, topicId, description: desc,
        date: item.date, timeFrom, timeTo,
        location: { venueName: venue, address },
        scope, visibility, visibleTo,
        showInAnnouncements: showAnn, requireConfirmation: reqConf,
        reminderDays, displayPriority,
        'attendance.invited': invited,
        updatedAt: new Date().toISOString(), updatedBy: createdBy
    };
    await db.collection('events').doc(_editingEventId).update(updateData);
    return;
}
```

Ważne: **`matchData` i resztę `attendance`** (confirmed/declined/decidedBy)
**update() nie nadpisuje** — tylko `attendance.invited` się zmienia. Dzięki
temu edycja nie zgubi trwającego meczu live ani dotychczasowych potwierdzeń
obecności.

### Powiadomienia

Nic nowego po stronie CF — `onEventUpdated` (branch B, już istniejący) sam
wykryje zmianę `date`/`timeFrom`/`timeTo`/`location.venueName` i wyśle
`EVENT_UPDATED` jak dotychczas. Jeśli edycja nie zmienia żadnego z tych 4
pól (np. tylko opis albo lista zaproszonych), CF nic nie wysyła — tak samo
jak przy evencie.

### Dla APP

Jeśli budujecie analogiczną edycję u siebie — warto pamiętać o tym samym:
nie nadpisywać `matchData`/`attendance.confirmed/declined` przy update,
i nie tworzyć nowego `eventId`.
