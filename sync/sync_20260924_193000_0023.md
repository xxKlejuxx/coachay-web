### Dokładnie jak działa „jedna najświeższa” (na wyraźną prośbę Rafała: „napisz do web jak to
zrobiłeś — dokładnie”)

Osobna funkcja `fetchLicenseInfo()` w `blocked.tsx` (NIE przez `getAccessStatus` — ta przy EXPIRED w
większości gałęzi celowo zwraca `expiryDate`/`willRenew` = null, więc traci informację PO co
zawiodło; do samego wyświetlenia czytamy źródła wprost):

1. Równolegle (`Promise.all`): `users/{uid}` (→ `subscription`), `clubs/{clubId}` (→ `license`),
   `access_rights` (`uid`+`club_id`), `memberships` tego usera w tym klubie (→ `usedSlot`).
2. Buduje listę kandydatów — TYLKO tych źródeł, które user kiedykolwiek miał (mają jakąkolwiek
   `expiresAt`/`valid_until`), niezależnie czy już wygasły:
   - `individual`: `users.subscription.expiresAt` (jeśli istnieje) + `willRenew`;
   - `family`: dokument `access_rights` z `source !== 'individual'` (analogicznie do P1 w
     `getAccessStatus`) → `valid_until` + `willRenew`;
   - `club`: `clubs.license.valid_until` (jeśli `clubs.license` istnieje) + `used`/`total` +
     `yourSlot` (`membership.usedSlot===1`).
3. Jeśli lista kandydatów NIE jest pusta: sortuje malejąco po dacie (`expiresAt`/`valid_until`) i
   bierze PIERWSZY — czyli ten, który wygasł (albo wygasa) NAJPÓŹNIEJ. To jest ten, który realnie
   tłumaczy dlaczego user jest zablokowany TERAZ — każda wcześniejsza data to stary, dawno
   nieaktualny zapis (np. licencja klubowa sprzed pół roku, którą user potem zastąpił indywidualną
   — nie chcemy pokazywać tamtej).
4. Jeśli lista kandydatów JEST pusta (user nigdy nie miał żadnej z tych trzech licencji): liczy
   trial jako `getFirstMembershipDate(uid, clubId) + 90 dni` (fallback: `clubs.createdAt + 90 dni`)
   i pokazuje go WYŁĄCZNIE jeśli już minął. Trial nigdy nie wchodzi do sortowania z resztą — to
   czysty fallback „zupełny brak licencji”.
5. Stan tekstowy (`aktywna`/`czeka na odnowienie`/`wygasła`) liczony osobno przy renderze:
   `expiresAt > teraz` → aktywna; inaczej, dla individual/family, `willRenew===true` → czeka na
   odnowienie; inaczej wygasła. Trial zawsze wygasł (pokazywany tylko gdy już minął).

Ta sama funkcja jest wołana ponownie po każdym „Sprawdź ponownie” (`await fetchLicenseInfo()` przed
odczytaniem wyniku `getAccessStatus`), więc po odnowieniu licencji panel pokazuje świeże dane, nie
te sprzed kliknięcia.
