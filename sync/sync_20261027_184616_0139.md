# Sync #0139 — WEB → MOBILE (2026-10-27)

## Bug: appka pokazuje "Invalid or expired code" dla poprawnych, nieużytych kodów

Rafał testował kody zaproszenia (rejestracja z kodem od trenera) na dwóch telefonach
testerskich — obydwa dostały komunikat **"Invalid or expired code."** mimo że te same
typy kodów działają bez problemu na jego własnym telefonie.

### Sprawdziliśmy bezpośrednio w Firestore — kody są w 100% poprawne

```
code: A6R7HQ   isUsed: false   expiresAt: 2026-11-19   type: RODZIC (Neo Kowalski)
code: WDUQXH   isUsed: false   expiresAt: 2026-11-19   type: RODZIC (Bartosz Lato)
```

Czyli to **nie jest problem z danymi/backendem** — kolekcja `inviteCodes` ma poprawne,
nieużyte, nieprzeterminowane dokumenty. Błąd musi być po stronie klienta (appki) na
tych konkretnych urządzeniach: albo stary/inny build apki na telefonach testerskich,
albo appka źle sanityzuje/porównuje wpisany kod.

### Jak to jest zrobione na WEB (dla porównania, działa poprawnie)

1. **Sanityzacja na żywo przy wpisywaniu** (każdy keystroke), nie tylko przed wysłaniem —
   usuwa WSZYSTKO poza wielkimi literami i cyframi (spacje, znaki niewidoczne ze
   schowka typu zero-width space, nowe linie z wklejenia itd.):

```js
oninput="this.value = this.value.toUpperCase().replace(/[^A-Z0-9]/g,'')"
```

2. **Dodatkowo `.trim().toUpperCase()`** tuż przed zapytaniem do Firestore (`blocked.html`,
   `redeemCode()`):

```js
const code = document.getElementById('invite-input').value.trim().toUpperCase();
```

3. **Rozróżnione komunikaty błędów** zamiast jednego ogólnego "nieprawidłowy kod" — to
   pomaga odróżnić "zły kod" od "wygasł" od "błąd sieci/połączenia":

```js
try {
    const snap = await db.collection('inviteCodes')
        .where('code', '==', code).where('isUsed', '==', false).limit(1).get();

    if (snap.empty) { /* → "Invalid code" */ return; }

    const codeData = snap.docs[0].data();
    if (codeData.expiresAt && codeData.expiresAt.toDate() < new Date()) {
        /* → "Expired code" (osobny komunikat od "nie znaleziono") */
        return;
    }
    // ... dalej zapis membership, oznaczenie isUsed: true ...

} catch (e) {
    console.error('redeemCode:', e);
    /* → "Connection error" — osobny komunikat, nie myl z "zły kod" */
}
```

Zestaw znaków samych kodów (generowanych na web) to tylko
`ABCDEFGHJKLMNPQRSTUVWXYZ23456789` (bez I, O, 0, 1 — unikamy pomyłek wzrokowych), więc
literówka typu "O" zamiast "0" i tak nie powinna się zdarzyć przy ręcznym wpisywaniu
poprawnego kodu.

### Prośba do MOBILE

1. Sprawdźcie, czy wejście z pola kodu jest sanityzowane identycznie (strip wszystkiego
   poza A-Z0-9, uppercase) — zwłaszcza jeśli tester **wkleja** kod ze SMS-a/wiadomości,
   bo wklejony tekst często niesie niewidoczne znaki (spacja na końcu, zero-width space,
   znak nowej linii), których `.trim()` sam nie złapie, jeśli jest w środku stringa.
2. Rozdzielcie komunikat błędu na min. 3 przypadki (brak kodu / kod wygasł / błąd
   połączenia) zamiast jednego "Invalid or expired code" — ułatwi to diagnozowanie
   takich przypadków w przyszłości, bo sam komunikat powie, co faktycznie się stało.
3. Zweryfikujcie wersję/build appki zainstalowaną na urządzeniach testerskich — jeśli to
   telefony z farmy testerskiej, upewnijcie się, że mają aktualny build wskazujący na
   projekt produkcyjny `coachay-5c3c9`, nie starszy/inny wariant.

Dajcie znać, czy po stronie appki faktycznie był brak sanityzacji/rozróżnienia błędów,
czy to jednak coś innego — mamy konkretne dwa kody (wyżej) gotowe do odtworzenia na
żywo, jeśli potrzebujecie.
