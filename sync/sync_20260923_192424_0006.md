## Temat: Audyt źródła membership — pole `createdBy` (decyzja Rafała)

**Decyzja:** zapisy zostają po stronie klientów (bez Cloud Functions), ale każdy NOWY dokument `memberships` ma obowiązkowe pole `createdBy`:
- panel WWW → `"WEB_PANEL"`
- aplikacja mobilna → `"MOBILE_APP"`

Cel: jeśli w testach zamkniętych jakiś rekord się rozjedzie (brak `clubId`, brak `usedSlot`, zły status itp.), od razu widać, która platforma go utworzyła.

### WEB — ✅ DONE (commit 53d2f71, Hosting wdrożony)

W `coachay-core.js` dodano `buildMembership(fields)`, wspólny szkielet dokumentu. Przechodzi przez niego wszystkie 14 miejsc tworzenia membership w web (`index.html`, `klub.html`, `profil.html`, `blocked.html`, `coachay-core.js`).

Szkielet (pola podane przez wywołującego mają pierwszeństwo, `createdBy` zawsze nadpisywane):
```js
{
  membershipId: null, userId: null, clubId: null, teamId: null, playerId: null,
  role: null, trainerRole: null, status: 'ACTIVE', displayName: '',
  isDemo: false, usedSlot: 0,
  joinedAt: new Date().toISOString(),
  createdAt: serverTimestamp(),
  createdBy: 'WEB_PANEL'
}
```
Dodatkowo w konsoli pojawia się `console.warn` przy braku `membershipId`/`role` i przy pustym `clubId`.

### APP — prośba

1. W każdym miejscu, gdzie aplikacja tworzy dokument `memberships`, dopisać `createdBy: 'MOBILE_APP'` (na sztywno).
2. Najlepiej analogicznie: jedna funkcja-szkielet w aplikacji z tym samym zestawem pól bazowych i domyślnych wartości jak wyżej, żeby struktura była identyczna.
3. `usedSlot: 0` domyślnie. Ważne dla zawodników bez konta (`userId: null`): `onMembershipCreated` kończy wtedy działanie od razu i nie ustawia `usedSlot`, a zadania nocne szukają `usedSlot == 0`.
4. `clubId` nigdy nie powinno być puste, jeśli membership ma `teamId`. W razie wątpliwości brać je z `teams/{teamId}.clubId`.

Proszę o potwierdzenie w #0007, gdy wdrożone (i od której wersji aplikacji).

### Uwagi

- Stare rekordy nie mają `createdBy`. Brak pola = rekord sprzed 2026-09-23 albo ze starej wersji aplikacji.
- Wielkość liter statusu (`active` / `ACTIVE`) celowo NIE została ujednolicona w tej zmianie, bo część zapytań szuka obu wariantów. To temat na osobną decyzję.
- `firestore.rules` bez zmian (nie wymuszają `createdBy`). Wymuszenie w regułach dopiero, gdy nie będzie w użyciu żadnej starej wersji aplikacji.
