# Sync #0138 — WEB → MOBILE (2026-10-26)

## Bug zgłoszony przez Rafała: przy dodawaniu nowego zawodnika pole "data urodzenia"
## pozwala wpisać cokolwiek — powinno być polem typu data

Zgłoszenie: w formularzu dodawania nowego zawodnika w APP pole daty urodzenia
przyjmuje dowolny wpis (wolny tekst), zamiast wymuszać poprawny format/zakres daty.
To otwiera drogę do zapisania nonsensownych wartości (np. literówka, zły format,
data w przyszłości, rok nierealny dla zawodnika danej kategorii wiekowej itd.),
co potem psuje wszystko, co liczy wiek na podstawie `birthDate` (etykiety grup
wiekowych, sortowanie, wyświetlanie "X lat" na karcie zawodnika).

### Jak to jest zrobione na WEB (działa poprawnie, jako punkt odniesienia)

`druzyna.html`, formularz dodawania/edycji zawodnika:

```html
<div class="form-group">
    <label class="form-lbl">Data urodzenia *</label>
    <input type="date" class="form-inp" id="ap-urodziny">
</div>
```

Natywny input `type="date"` wymusza poprawny format (kalendarz/picker), więc nie da
się wpisać dowolnego tekstu — przeglądarka sama waliduje format `YYYY-MM-DD`.

### Prośba do MOBILE

Zamieńcie pole tekstowe/free-text na natywny date picker (lub odpowiednik na
Androidzie/iOS — `DatePicker`/`UIDatePicker` itp.), żeby:
1. Nie dało się wpisać dowolnego tekstu zamiast daty.
2. Warto dodać sensowny `min`/`max` zakres (np. nie data w przyszłości, nie sprzed
   ~100 lat) — na web tego jeszcze nie ma (`<input type="date">` bez `min`/`max`),
   więc jeśli to dodacie u siebie, dajcie znać — dorobimy to samo na web.
3. Pole wymagane (`*` już jest w etykiecie) — upewnijcie się, że zapis bez daty jest
   blokowany tak jak Imię/Nazwisko/Grupa.

Zapis idzie do `players/{playerId}.birthDate` jako string `YYYY-MM-DD` (zgodnie z
formatem, jakiego używamy wszędzie indziej w Firestore na dacie, np. `events.date`),
żeby schemat się zgadzał między web i appką.
