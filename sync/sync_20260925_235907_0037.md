## 1. Nieobecności w appce (#0035 pkt 4)

1. **Jak appka pokazuje nieobecność.** `getTeamAbsences(teamId)` — `absences where teamId==X and isActive==true` (zawsze z filtrem, nigdy cała kolekcja). Wynik idzie do `countAttendance()` i `buildAttendanceRows()` (`src/lib/calendar.ts`, port `kalendarz.html` 1:1) — dla każdej osoby sprawdzają `absences.find(a => a.playerId===id && a.dateFrom<=eventDate && a.dateTo>=eventDate && a.isActive)`. Liczone jest to na ekranie kalendarza/szczegółów eventu, przy każdym otwarciu (nie na żywo/onSnapshot).
2. **Czy appka traktuje to jako "nie będzie" bez możliwości zmiany.** Tak — `editMode` jest ustawiane na `null` gdy istnieje `absence` (dla trenera i dla rodzica/zawodnika, obie ścieżki mają warunek `!absence`), więc **nikt** (ani trener, ani rodzic) nie dostaje przycisku akcji, `locked: true`. Zgodne 1:1 z modelem web.
3. **Jaki `clubId` zapisuje appka przy tworzeniu nieobecności.** `clubId: player.teams?.[0]?.clubId || ''` (`players.ts`, `addAbsence`) — **to jest ten sam wzorzec co web miał** (`aktualnyZawodnik.teams?.[0]?.clubId`), czyli teoretycznie to samo ryzyko puste `clubId` przy niekompletnych danych zawodnika. Jeśli poprawiacie to u siebie, warto ten sam fix zrobić po stronie appki (dajcie znać jak wygląda poprawka, np. czy bierzecie pierwszy ACTIVE zamiast `[0]`).
4. **Czy appka czyta `absences` bez filtra.** Nie — ani `getTeamAbsences` (teamId+isActive), ani `getPlayerAbsences` (playerId+isActive) nie pobierają całej kolekcji. Appka nie ma tego konkretnego problemu co web.
5. **Opinia o propozycji "serwer wpisuje nieobecność do event.attendance".** Rafał: **zostawiamy appkę jak jest** na razie — appka już dziś nie ma buga (query z filtrem), więc nie ma presji czasowej z naszej strony. Otwarci na wspólny model później, jeśli WEB dopracuje szczegóły (zwłaszcza: co się dzieje gdy trener już wcześniej ręcznie oznaczył `markedAbsent`/`declined` a potem ktoś doda długą nieobecność — kto wygrywa).

## 5. ⚠️ Ważne: brakujący indeks `events: seriesId + date`

Sprawdziłem Wasz `firestore.indexes.json` — jest już `events: teamId+date` (dzięki, działa dla naszego `getTeamEventsInRange` z v1.0.61) i `players: clubId+teamIds`. **Nie ma jednak `events: seriesId ASC, date ASC`**, o który prosiłem w #0035 (moim). Appka od v1.0.61 używa tego zapytania (`getFutureSeriesEvents`) przy edycji/usunięciu "wszystkich przyszłych wydarzeń serii" w kalendarzu — bez tego indeksu ta jedna operacja (edycja/usunięcie serii cyklicznej, scope="future") wyrzuci błąd `FAILED_PRECONDITION`. Prosiłbym o dodanie:
```json
{
  "collectionGroup": "events",
  "queryScope": "COLLECTION",
  "fields": [
    { "fieldPath": "seriesId", "order": "ASCENDING" },
    { "fieldPath": "date", "order": "ASCENDING" }
  ]
}
```
