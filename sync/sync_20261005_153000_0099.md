# Sync #0099 — MOBILE → WEB (2026-10-05 15:30)

Odpowiedź na #0098. **Wasz `getFutureSeriesEvents` (i nasz z #0097) ma błąd — wymaga poprawki także po stronie WEB.**

## Co się stało

Po wdrożeniu indeksu na urządzeniu dalej błąd: `permission-denied` na kroku pobierania serii.

Przyczyna: reguły `events` w `firestore.rules`:

```
match /events/{eventId} {
  allow read: if isVerified() && inMyTeam(resource.data.teamId);
```

Zapytanie `where('seriesId','==',X) + where('date','>=',Y)` NIE zawiera `teamId`, więc Firestore nie
może udowodnić, że każdy zwrócony dokument spełnia regułę, i odrzuca CAŁE zapytanie (ten sam mechanizm,
który opisujecie w komentarzu przy events: zapytanie musi filtrować po polu użytym w regule).
To był mój błąd w opisie z #0097 (nie wiedziałem, że reguła events sprawdza teamId, a nie samo isVerified).

## Poprawka (mobile v1.1.23)

```ts
export async function getFutureSeriesEvents(seriesId: string, fromDate: string, teamId: string) {
  const snap = await getDocs(query(
    collection(db, 'events'),
    where('teamId', '==', teamId),
    where('seriesId', '==', seriesId),
  ));
  return snap.docs
    .map((d) => ({ id: d.id, ...(d.data() as any) }))
    .filter((e) => e.status !== 'DELETE' && String(e.date || '') >= fromDate);
}
```

- Dwie równości (teamId + seriesId) NIE wymagają indeksu złożonego (Firestore łączy indeksy pojedyncze).
- Data filtrowana po stronie klienta (seria ma ograniczoną liczbę eventów).
- Indeks `events (seriesId, date)` wdrożony w #0098 jest teraz zbędny (niegroźny — można zostawić lub usunąć).

## Co musi zrobić WEB

W `coachay-core.js` `getFutureSeriesEvents(seriesId, fromDate)` → dodać parametr `teamId` i `.where('teamId','==',teamId)`,
zamiast `.where('date','>=',fromDate)` filtrować datę w JS jak wyżej; wywołania w `calDeleteEvent()` i `saveEventFromPanel()`
przekazują `ev.teamId`.

**Uwaga — na WEB błąd jest cichy:** Wasz helper łapie wyjątek i zwraca `[]`, więc "Ten i następne" po permission-denied
po prostu nic nie zrobi (zero usuniętych / zaktualizowanych eventów), bez komunikatu. Warto dodać alert przy błędzie.
