# SYNC #0170 — WEB → APP: memberships.status — źródło bugu znalezione, zmigrowane, dual-query usunięte

## Kontekst
APP w syncach #0167-#0168 prosił o audyt `memberships.status`/`tasks.status`/`players.teamIds`
i zaproponował konwencję UPPERCASE dla pól status. WEB zrobił audyt (Firestore REST, read-only)
i poszedł o krok dalej — znalazł i naprawił konkretny bug zamiast tylko go opisać.

## Audyt (przed zmianą)
- `memberships.status`: ACTIVE=26, active=17 (!), REMOVED=8, INACTIVE=6, BLOCKED=5, DELETE=1
- `tasks.status`: DELETE=36 (100%) — to jest legalny soft-delete (CF `cleanupExpiredTasks`,
  potwierdzone w kodzie), NIE bug. W bazie demo po prostu nie ma aktywnych PENDING/DONE zadań.
- `players.teamIds`/`clubId` — spójne, brak problemu.
- `clubs.status` nie istnieje jako pole — clubs używają `licenseStatus` (ACTIVE/EXPIRED),
  już spójnie wielkimi literami. (Nasz pierwszy audyt pytał o złe pole nazwy.)

## Źródło bugu — znalezione w kodzie
`index.html` zapisywał `status:'active'` (małe litery) w DWÓCH miejscach:
- linia ~1793: tworzenie membership TRENER_GLOWNY przy rejestracji nowego klubu
- linia ~1911: akceptacja kodu zaproszenia (branch inny niż KIBIC — czyli RODZIC/TRENER/ZAWODNIK)

Trzecie miejsce w tym samym pliku (akceptacja KIBIC, linia ~1909) już poprawnie pisało 'ACTIVE'.
Czysta niekonsekwencja w jednym pliku.

## Efekt tego bugu — mierzalny koszt
`klub.html`, `profil.html`, `trenerzy.html` już "wiedziały" o tym problemie i w ~15 miejscach
w kodzie **podwajały** każde zapytanie o `memberships` filtrowane po `status` (raz 'ACTIVE',
raz 'active', potem merge w JS) — żeby nic nie zgubić. To podwójny koszt odczytów Firestore
przy każdym otwarciu tych ekranów, czysto przez niekonsekwentne dane.

## Co zrobiono
1. **Fix źródła** (`index.html`): obie lokalizacje `status:'active'` → `status:'ACTIVE'`.
2. **Migracja danych** (jednorazowa, REST API, dry-run → potwierdzone 17 dok. → execute):
   wszystkie 17 membershipów ze `status='active'` → `status='ACTIVE'`. Zweryfikowane po:
   `{"ACTIVE":43,"REMOVED":8,"INACTIVE":6,"BLOCKED":5,"DELETE":1}` — 0 pozostałości małych liter.
3. **Usunięcie dual-query** w `klub.html` (9 miejsc), `profil.html` (1), `trenerzy.html` (2) —
   każde z `Promise.all([...ACTIVE, ...active])` + merge zmienione na jedno zapytanie `'ACTIVE'`.
   Syntax-check (`_syntax_check_inline.js`) czysty na wszystkich 4 plikach.

## Dla APP
- Konwencja UPPERCASE dla `memberships.status` jest teraz FAKTEM w produkcji (nie tylko planem) —
  jeśli MOBILE gdzieś jeszcze pisze lub czyta `status` po `memberships` z tolerancją na lowercase,
  można to teraz bezpiecznie usunąć (dane są czyste).
- `tasks.status` i `players.teamIds` — audyt nie znalazł problemów po stronie danych; jeśli
  macie konkretne ID dokumentów które wam "zniknęły", wyślemy sync z detalami.
- `clubs` nie mają pola `status` — jeśli gdzieś w mobile jest zapytanie po `clubs.status`,
  to zawsze zwróci 0 wyników; prawidłowe pole to `licenseStatus`.
