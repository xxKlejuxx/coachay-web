## Temat: `forName` w `inviteCodes` — koniec zgadywania imienia/nazwiska

### Kontekst / problem znaleziony przez Rafała
Ekran rejestracji kodem (`index.html → checkInviteCode()`) dziś rozbija pojedynczy string
na imię/nazwisko zgadując po spacji:

```js
// index.html:1621-1627 (STAN OBECNY)
if (!needsName && prefilledName) {
    var parts = prefilledName.trim().split(' ');
    fnameEl.value = parts[0]||''; lnameEl.value = parts.slice(1).join(' ')||'';
    fnameEl.readOnly = true; lnameEl.readOnly = true;
    ...
}
```

Dla dwuczłonowego **imienia** (np. „Anna Maria Kowalska”) to się psuje: imię = „Anna”,
nazwisko = „Maria Kowalska”. Dwuczłonowe nazwisko akurat działa OK (reszta i tak ląduje
w nazwisku), ale to przypadek.

### Kluczowe ustalenie: nie trzeba zgadywać — dane źródłowe już mają osobne pola
Sprawdzone bezpośrednio w kodzie (nie zgadywane):

- **`trainers`** (`trenerzy.html:1176-1182`, `saveNewTrainer()`) zapisuje:
  ```js
  const trainerData = {
      displayName: name,   // sklejone
      firstName,           // OSOBNO
      lastName,            // OSOBNO
      ...
  };
  ```
- **`players`** (`druzyna.html:1767-1792` i `:2487-2510`) zapisuje:
  ```js
  firstName, lastName, name: fullName,   // OSOBNO
  ```

Problem jest wyłącznie w miejscu **generowania kodu zaproszenia** — tam już sklejamy
`firstName + ' ' + lastName` w jeden string, zanim trafi do `inviteCodes.forName`:

- `trenerzy.html:1179`: `const name = (firstName + ' ' + lastName).trim();`
  → wywołania `_generateCode(trainerId, name, role)` w 3 miejscach: **linie 1209, 1356, 1418**.
- `trenerzy.html:1222-1244` (`_generateCode`): zapisuje `forName` (= już sklejony `name`) do
  dokumentu `inviteCodes`.
- `druzyna.html:1596-1618` (`codeDoc` dla kodów ZAWODNIK/RODZIC): **w ogóle nie ma pola
  `forName`** — jest tylko `playerName: aktualnyZawodnik.name || (firstName+' '+lastName)`.
  Fallback w `index.html:1613-1617` dla ZAWODNIK i tak doszukuje się w `players/{playerId}`
  i bierze `.name`/`.displayName` (znowu sklejone, znowu do rozbicia).
