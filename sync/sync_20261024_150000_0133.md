# Sync #0133 — WEB → MOBILE (2026-10-24)

## BUG: nowy user bez dokończonego onboardingu nie może się ponownie zalogować

Kontynuacja wątku testerów z 20testers (patrz #0129/#0130-MOBILE). Zdiagnozowaliśmy konkretny przypadek.

### Co się stało u testerów

Sprawdziliśmy w Firestore 2 konta testerów (`remobtester8@gmail.com`, `remobtesterfour4@gmail.com`):
- `emailVerified: true` — zweryfikowani OK.
- `users` + `authIndex` doc istnieją poprawnie.
- Membership: `role: TRENER_GLOWNY`, `status: "active"`, **`teamId: null`**, `createdBy: "MOBILE_APP"`.

Czyli: zarejestrowali się w appce jako **nowy trener zakładający własny klub** (a nie kodem
zaproszenia — sprawdziliśmy też 19 kodów RODZIC, które im przekazał Rafał: **wszystkie `isUsed: false`,
żaden nie został użyty**). Problem: po założeniu klubu **nie dokończyli zakładania drużyny** (nie ma
żadnego membershipu z `teamId`). Gdy wylogowali się / zamknęli appkę i spróbowali zalogować się
ponownie, appka zrzuca ich z powrotem na ekran logowania zamiast pozwolić dokończyć onboarding.

### Root cause (hipoteza, oparta na tym jak to działa na web)

Na webie (`start.html`) sesja po zalogowaniu jest budowana przez `initSession()`, która zwraca
`{ user, team, membership }` — **`team` może być `null`**, to nie jest traktowane jako błąd sesji.
Dopiero DALEJ jest osobna, świadoma obsługa:

```js
const session = await initSession();
if (!session) { /* to jest faktyczny brak sesji -> signOut + redirect do index.html */ }
...
const { user, team, membership } = session;
if (!team) {
    // user ma konto i membership klubowe, ale nie ma jeszcze drużyny — NIE wylogowujemy,
    // tylko kierujemy do ekranu zakładania drużyny
    sessionStorage.setItem('noTeamRedirect', '1');
    window.location.href = 'klub.html';
    return;
}
```

Czyli web rozróżnia dwa różne stany: "brak sesji/konta" (prawdziwy błąd → wyloguj) vs. "jest konto
i klub, ale nie ma jeszcze drużyny" (to normalny, niedokończony onboarding → pokaż ekran zakładania
drużyny, NIE wylogowuj).

**Pytanie/prośba do MOBILE**: sprawdźcie, czy wasza logika po zalogowaniu robi to samo rozróżnienie,
czy traktuje "brak membershipu z teamId" jako nieprawidłową sesję i robi sign-out → powrót do
logowania. Jeśli tak — to jest dokładnie ten bug. Każdy user, który zarejestruje się, założy klub,
ale z jakiegoś powodu nie dokończy zakładania drużyny w tej samej sesji (zamknie appkę, straci
zasięg, cokolwiek), **nigdy nie będzie mógł wrócić i dokończyć** — będzie w nieskończonej pętli
logowanie → wylogowanie.

Rekomendacja: skopiować podejście z web — rozdzielić "nie ma sesji w ogóle" od "jest sesja, ale brak
drużyny" i w tym drugim przypadku kierować do ekranu zakładania pierwszej drużyny, zamiast do logowania.
