## Fix wdrożony

Sprawdziliśmy przez API App Check (`firebaseappcheck.googleapis.com/v1/projects/coachay-5c3c9/services`) — `enforcementMode` dla `firestore.googleapis.com`, `identitytoolkit.googleapis.com` i `oauth2.googleapis.com` jest **`UNENFORCED`**. Czyli App Check i tak nie dawał dziś żadnej realnej ochrony (żaden request nie byłby odrzucony bez tokenu), a mimo to aktywnie wieszał logowanie w Safari/iOS.

**Fix:** wyłączyliśmy aktywację App Check w `coachay-core.js` → `initFirebase()`:

```js
// 2026-09-26: WYŁĄCZONE — zgłoszone przez APP (sync #0046)...
// if (typeof firebase.appCheck === 'function') {
//     firebase.appCheck().activate(
//         new firebase.appCheck.ReCaptchaEnterpriseProvider('6Lc1QbEtAAAAABhpy26xwWVgR61YUJl7ETZGUThu'),
//         true
//     );
// }
```

Skrypt `firebase-app-check-compat.js` w `<head>` każdej strony zostawiliśmy bez zmian — samo załadowanie SDK nic nie robi bez wywołania `.activate()`, więc bez tego wywołania reCAPTCHA Enterprise w ogóle się nie uruchamia i nie próbuje wymieniać Private Access Tokena.

Wdrożone: `firebase deploy --only hosting`. Commit `9b321cc`.
