## 1) `forName` = `firstName|lastName` zamiast zgadywania po spacji

**`trenerzy.html`** — 3 wywołania `_generateCode()` zmienione, żeby przekazywać
`firstName`/`lastName` sklejone znakiem `|` zamiast gotowego `displayName`:
- `saveNewTrainer()`: `_generateCode(trainerId, firstName + '|' + lastName, role)`
- 2x regeneracja kodu (`regenerateCode`-podobne funkcje, operujące na `t = detailTrainer`):
  `_generateCode(t.trainerId, (t.firstName||'') + '|' + (t.lastName||''), t.role)`

**`druzyna.html`** — `codeDoc` dla kodów ZAWODNIK/RODZIC dostał nowe pole (obok
istniejącego `playerName`):
```js
forName: (aktualnyZawodnik.firstName||'') + '|' + (aktualnyZawodnik.lastName||''),
```

**`index.html`** (`checkInviteCode()`) — rozbijanie `prefilledName` rozpoznaje
teraz `|` jako separator; stare kody bez `|` (wygenerowane przed tą zmianą) dalej
fallbackują na zgadywanie po spacji, więc nic co już wisi w bazie się nie psuje:
```js
var fn, ln;
if (prefilledName.indexOf('|') !== -1) {
    var p = prefilledName.split('|');
    fn = p[0] || ''; ln = p.slice(1).join('|') || '';
} else {
    var parts = prefilledName.trim().split(' ');
    fn = parts[0] || ''; ln = parts.slice(1).join(' ') || '';
}
fnameEl.value = fn; lnameEl.value = ln;
window._regName = { fname: fn, lname: ln };
```

Efekt: dla NOWYCH kodów (wygenerowanych po tym deployu) imię/nazwisko jest zawsze
dokładne, bez żadnego zgadywania — niezależnie od liczby członów w imieniu czy
nazwisku.

## 2) Pełny reset przy "Zmień kod" + ochrona przed wyścigiem (race condition)

**`resetCodeStep()`** czyści teraz WSZYSTKO co poprzedni `checkInviteCode()`
mógł ustawić: pola imię/nazwisko (wartość + readOnly + opacity), etykietę
dziecka w bloku zgody, odznakę roli, nazwę drużyny — nie tylko `_inviteCode`
i input kodu jak wcześniej.

**`checkInviteCode()`** dostał token sekwencyjny (`window._codeCheckSeq`), z
dwoma punktami kontrolnymi po każdym `await` (zapytanie `inviteCodes`, potem
`teams`) — jeśli w międzyczasie wystartowało już nowsze sprawdzenie kodu (user
zdążył wpisać/poprawić kod zanim poprzednie zapytanie wróciło), starsze
wywołanie przerywa się cicho i NIE dotyka już DOM-u ani `window._inviteCode`.
To zamyka możliwość, że wolniejsza odpowiedź dla STAREGO kodu nadpisze dane
nowszego, poprawnego sprawdzenia — co było najbardziej prawdopodobnym
wyjaśnieniem zgłoszenia Rafała (dziecko z pierwszego kodu widoczne po wpisaniu
drugiego).
