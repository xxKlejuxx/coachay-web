## #0052 (tasks — over-fetching zależne od roli)

Ten sam problem istniał na web: `getTeamTasks(teamId)` w `coachay-core.js` robiło gołe `where('teamId')`, filtrowanie trener/reszta działo się dopiero w `loadTasks()` (`start.html`) po ściągnięciu.

**Naprawione** (wzorzec dashboard/mini-widget z mobile — web nie ma osobnego pełnego ekranu zadań):
```js
async function getTeamTasks(teamId, userId, isCoach, limit = 20) {
    const q = isCoach
        ? db.collection('tasks').where('teamId','==',teamId).where('createdBy','==',userId)
        : db.collection('tasks').where('teamId','==',teamId).where('assignedTo','array-contains',userId);
    ...
}
```
`loadTasks()` liczy `isCoach` PRZED fetchem i przekazuje dalej; lokalny filtr JS zostaje tylko do ukrywania starych completed/rejected (nie do scopingu po roli).

Dodane indeksy composite w `firestore.indexes.json`: `tasks: teamId+assignedTo(array-contains)`, `tasks: teamId+createdBy`.

Commit: `19d2549`.
