## 2. ZADANIA — usuwanie (`deleteTaskFromDashboard`)

```js
async function deleteTaskFromDashboard(taskId) {
    try {
        const doc = await db.collection('tasks').doc(taskId).get();
        if (!doc.exists) return;
        const task = doc.data();
        if (!confirm(`Usunąć zadanie "${task.title || ''}"? Wszyscy przypisani dostaną powiadomienie o usunięciu.`)) return;
        await db.collection('tasks').doc(taskId).update({
            status: 'DELETE', deletedAt: new Date().toISOString(), deletedBy: getCurrentUserId()
        });
        await manageNotifications('delete', 'task', taskId, { teamId: task.teamId || _activeTeamId, assignees: task.assignedTo || [], title: task.title || '' });
        await refreshDashboard();
    } catch (e) { console.error('❌ deleteTaskFromDashboard', e); alert('Błąd: ' + e.message); }
}
```

Jedyne sprawdzenie uprawnień: przycisk renderuje się tylko w `isSender` branchu karty
(`task.createdBy === userId`) — żadnego dodatkowego sprawdzenia roli przy samym zapisie do
Firestore. Jeśli Wasz bug to permission-denied z reguł bezpieczeństwa na `tasks`, to
współdzielone między platformami — u nas ten konkretny zapis (`status`+`deletedAt`+
`deletedBy`, bez innych zmian) przechodzi bez błędu.

Ważne: `manageNotifications('delete', ...)` dla `referenceType==='task'` wysyła NOWE
powiadomienie "Zadanie usunięte" (zmiana z #0082, wcześniej ta akcja tylko archiwizowała
stare powiadomienia). Jeśli Wasze `deleteNotificationsForReference()` robi tylko to drugie,
to różnica w zachowaniu — warto rozważyć ujednolicenie, ale to już osobna sprawa od bugu.

## 4. EVENTY — odwołanie (`calCancelEvent`)

```js
async function calCancelEvent() {
    if (!calDetailEvent) return;
    if (!confirm('Odwołać to wydarzenie? Wszyscy zaproszeni dostaną powiadomienie.')) return;
    const ev = calDetailEvent;
    const evId = ev.eventId || ev.id;
    try {
        await db.collection('events').doc(evId).update({ status: 'CANCELLED', cancelledAt: new Date().toISOString(), cancelledBy: getCurrentUserId() });
        const idx = calAllEvents.findIndex(e => (e.eventId||e.id) === evId);
        if (idx >= 0) calAllEvents[idx] = { ...calAllEvents[idx], status: 'CANCELLED' };
        openCalDetailPanel({ ...ev, status: 'CANCELLED' });
        renderCalGrid();
        const d = calSelectedDate;
        if (d) renderDayInspector(d);
        if (typeof clearTeamEventsCache === 'function') clearTeamEventsCache(_activeTeamId);
        await refreshDashboard();
    } catch(e) { console.error('❌ calCancelEvent', e); alert('Błąd: ' + e.message); }
}
```

Powiadomienia dla eventów NIE idą z klienta — wyłącznie z Cloud Function `onEventUpdated`
(komentarz w kodzie: "aby uniknąć duplikatów z race condition"). CF wykrywa przejście
`status !== 'CANCELLED' → 'CANCELLED'`, dezaktywuje stare powiadomienia (ATTENDANCE/CREATED)
o tym evencie, i wysyła nowe `EVENT_CANCELLED` do wszystkich zaproszonych
(`resolveInvitedUserIds`).

## 5. EVENTY — usuwanie (`calDeleteEvent`)

```js
async function calDeleteEvent() {
    if (!calDetailEvent) return;
    if (!confirm('Usunąć to wydarzenie?')) return;
    const ev = calDetailEvent;
    const evId = ev.eventId || ev.id;
    try {
        await db.collection('events').doc(evId).update({
            status: 'DELETE', deletedAt: new Date().toISOString(), deletedBy: getCurrentUserId(),
        });
        calAllEvents = calAllEvents.filter(e => (e.eventId||e.id) !== evId);
        closeCalDetailPanel();
        renderCalGrid();
        const d = calSelectedDate;
        if (d) renderDayInspector(d);
    } catch(e) { console.error('❌ calDeleteEvent', e); alert('Błąd: ' + e.message); }
}
```

Sprawdziliśmy `onEventUpdated` (CF) dla tego przypadku: `status: 'DELETE'` nie trafia w
branch "A: Odwołanie" (sprawdza wyłącznie `=== 'CANCELLED'`), trafia w branch "B: zmiana
daty/godziny/miejsca" (bo `status !== 'CANCELLED'` jest prawdą), ale tam liczą się tylko
różnice w `date`/`timeFrom`/`timeTo`/`venueName` — przy usunięciu nic z tego się nie zmienia,
więc `changes.length === 0` i funkcja wychodzi bez wysłania czegokolwiek. **Usunięcie eventu
na WWW jest całkowicie ciche — zero powiadomienia do zaproszonych.** (Inaczej niż przy
zadaniach, gdzie teraz usunięcie WYSYŁA powiadomienie — niekonsekwencja między eventami i
zadaniami po naszej stronie, zgłaszamy FYI, nie prosimy o nic konkretnego.)
