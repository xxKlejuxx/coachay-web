# Sync #0096 — WEB → APP

**Data:** 2026-10-05
**Od:** WEB
**Temat:** Jak WEB utrzymuje wybraną drużynę między ekranami (trener z 2+ drużynami) — do naprawy po stronie APP

## Zgłoszony problem (dotyczy APP, nie WEB)

Trener ma 2 drużyny (np. 2015 i 2005). Wybiera 2005 na ekranie start, przechodzi na ekran "Drużyna" — tam widzi 2015 (błędnie). WEB nie ma tego problemu, bo wybór drużyny jest trzymany w jednym, trwałym miejscu i każdy ekran go odczytuje na nowo — a nie w zmiennej w pamięci, która resetuje się przy zmianie ekranu.

## Jak to działa na WEB — model

**Źródło prawdy jest DWA razy zapisane, z priorytetem przy odczycie:**
1. `users/{userId}.selectedMembershipId` w Firestore — **trwałe**, przeżywa reinstall/relogin na innym urządzeniu.
2. `localStorage.selectedMembershipId` — szybki lokalny cache w przeglądarce (unika round-tripu do Firestore na każdym ekranie).

Kolejność odczytu (priorytet): **Firestore (`user.selectedMembershipId`) > localStorage > pierwsze aktywne membership** jeśli obu brak.

**Najważniejsze: każdy ekran, przy każdym wejściu, odpytuje to źródło NA NOWO** — nie ma globalnej zmiennej JS, która przenosiłaby się między ekranami (na WEB to w ogóle nie zadziałałoby — każde przejście między `start.html`/`druzyna.html` to pełny reload strony, świeży kontekst JS). Mechanizm działa WYŁĄCZNIE dzięki temu, że wybór jest odczytywany z trwałego store'a (localStorage/Firestore) na starcie każdego ekranu — nie dzięki przekazywaniu stanu między ekranami.

## Kod — zapis wyboru (przełącznik drużyny, `coachay-core.js`)

```js
// Przełącz drużynę (ctx-switcher) — zapisuje selectedMembershipId do localStorage + Firestore
async function switchTeam(membershipId, teamName) {
    if (!db || !membershipId) return;
    const userId = getCurrentUserId();

    // Weryfikacja statusu membership przed przełączeniem
    try {
        const mDoc = await db.collection('memberships').doc(membershipId).get();
        if (!mDoc.exists) { showCtxMsg('Nie znaleziono membership dla tej drużyny.'); return; }
        const st = mDoc.data().status;
        if (st === 'BLOCKED') { showCtxMsg(`Twój dostęp do drużyny "${teamName}" jest zablokowany.`); return; }
        if (st === 'REMOVED') { showCtxMsg(`Nie jesteś już członkiem drużyny "${teamName}".`); return; }
        // INACTIVE — archiwum po transferze, pozwalamy wejść (tryb tylko do odczytu)
    } catch(e) { console.warn('switchTeam weryfikacja:', e); }

    closeCtxOv();
    localStorage.setItem('selectedMembershipId', membershipId);
    try {
        await db.collection('users').doc(userId).update({ selectedMembershipId: membershipId });
    } catch(e) { console.warn('switchTeam zapis Firestore:', e); }
    window.location.reload();
}
```

Kluczowe: zapis idzie **od razu w dwa miejsca** (localStorage + Firestore), zanim ekran się przeładuje. Dzięki temu kolejny ekran (po reloadzie) widzi już nową wartość niezależnie od tego, które z tych dwóch źródeł odczyta pierwsze.

## Kod — odczyt wyboru na starcie KAŻDEGO ekranu (`initSession()`, `coachay-core.js`)

```js
// 3. Wybierz membership — z Firestore user doc lub localStorage (selectedMembershipId)
//    Priorytet: user.selectedMembershipId (Firestore) > localStorage > pierwsze aktywne
const selectedId = user.selectedMembershipId || localStorage.getItem('selectedMembershipId');
let membership = allMemberships.find(m => m.id === selectedId);

// 3a. Jeśli wybrany membership nie jest aktywny — sprawdź jego status
if (selectedId && !membership) {
    try {
        const mDoc = await db.collection('memberships').doc(selectedId).get();
        if (mDoc.exists) {
            const st = mDoc.data().status;
            if (st === 'BLOCKED' || st === 'REMOVED') {
                // Szukaj innego aktywnego membership
                if (allMemberships.length > 0) {
                    membership = allMemberships[0];
                    localStorage.setItem('selectedMembershipId', membership.id);
                    try { await db.collection('users').doc(userId).update({ selectedMembershipId: membership.id }); } catch(e) {}
                } else {
                    if (!window.location.href.includes('blocked.html')) window.location.href = 'blocked.html';
                    return null;
                }
            } else if (st === 'INACTIVE') {
                // Archiwum — pozwól wejść tylko do odczytu
                membership = { id: mDoc.id, ...mDoc.data(), isReadOnly: true, _isArchive: true };
            }
        }
    } catch (e) {}
    if (!membership) membership = allMemberships[0];
}
// ...
if (!membership) membership = allMemberships[0];

// Zapisz wybrany membership do localStorage (synchronizacja) — np. gdy przyszło z Firestore, a localStorage jest stare
if (membership.id !== selectedId) {
    localStorage.setItem('selectedMembershipId', membership.id);
}
```

Krótsza wersja tej samej logiki, używana np. przez `getCurrentMembership()`:

```js
async function getCurrentMembership() {
    const userId = getCurrentUserId();
    if (!db || !userId) return null;
    try {
        const selectedId = localStorage.getItem('selectedMembershipId');
        if (selectedId) {
            const doc = await db.collection('memberships').doc(selectedId).get();
            if (doc.exists && doc.data().userId === userId) return { id: doc.id, ...doc.data() };
        }
        // fallback: pierwsze aktywne membership
        const [snapNew, snapLegacy] = await Promise.all([
            db.collection('memberships').where('userId', '==', userId)
                .where('status', 'in', ['active', 'ACTIVE', 'grace', 'demo']).limit(1).get(),
            db.collection('memberships').where('userId', '==', userId)
                .where('isActive', '==', true).limit(1).get()
        ]);
        const doc = snapNew.docs[0] || snapLegacy.docs[0];
        if (!doc) return null;
        const m = { id: doc.id, ...doc.data() };
        if (m.status === 'BLOCKED' || m.status === 'REMOVED') return null;
        return m;
    } catch (e) {
        console.error('❌ getCurrentMembership:', e);
        return null;
    }
}
```

**Każdy ekran WEB** (`start.html`, `druzyna.html`, `klub.html`, `profil.html`, `raporty.html`, ...) na starcie woła `initSession()` (albo `getCurrentTeam()`/`getCurrentMembership()`), a nie trzyma własnego, niezależnego sposobu ustalania "aktualnej drużyny". To jest moim zdaniem najważniejszy punkt do sprawdzenia u APP — jeśli ekran "Drużyna" ma własną, odrębną logikę wyboru drużyny (np. zawsze bierze pierwszy membership z listy), to będzie ignorować to, co user wybrał na ekranie start, niezależnie od tego, czy gdzieś w aplikacji jest zapisany wybór.

## Co prawdopodobnie trzeba zrobić po stronie APP

1. **Jedno trwałe miejsce wyboru**, analogicznie do WEB:
   - `users/{userId}.selectedMembershipId` w Firestore (już istnieje w bazie — WEB i APP współdzielą tę samą kolekcję `users`, to pole już tam jest, niezależnie kto je ustawił).
   - Lokalny trwały cache po stronie APP — `AsyncStorage` (odpowiednik `localStorage` w RN) pod tym samym kluczem semantycznym, np. `selectedMembershipId`.

2. **Zapis przy przełączeniu drużyny** (przełącznik drużyny w APP) — zapisać w obu miejscach, analogicznie do `switchTeam()` powyżej:
   ```js
   await AsyncStorage.setItem('selectedMembershipId', membershipId);
   await firestore().collection('users').doc(userId).update({ selectedMembershipId: membershipId });
   ```

3. **Odczyt na KAŻDYM ekranie** (nie tylko na starcie aplikacji) — każdy ekran, który potrzebuje "aktualnej drużyny", musi odpytać to samo trwałe źródło na nowo, zamiast czytać je raz przy starcie apki i trzymać w Context/Redux bez odświeżania. Najprościej: funkcja `getCurrentMembership()` / `getCurrentTeam()` wołana w `useEffect`/`useFocusEffect` na każdym ekranie (albo w jednym miejscu — np. root-level hook/selector, który re-czyta Firestore+AsyncStorage przy każdym focus ekranu), z tą samą logiką priorytetu: **Firestore → AsyncStorage → pierwsze aktywne membership**.

   Jeśli obecnie APP trzyma wybraną drużynę w Context/Redux ustawionym raz przy starcie apki (a potem każdy ekran czyta z tego Context, ale ekran "Drużyna" ma jakiś inny/dodatkowy fallback który nadpisuje to pierwszym membershipem) — to jest dokładnie ten bug. Rozwiązanie: ekran "Drużyna" (i każdy inny) musi czytać ten sam, jeden selector/hook co ekran start, a nie liczyć aktualną drużynę samodzielnie.

4. Gdyby chcieli użyć `useFocusEffect` z React Navigation do re-weryfikacji przy każdym wejściu na ekran (żeby złapać zmianę zrobioną na innym ekranie w tej samej sesji) — to bezpieczny wzorzec, WEB robi coś równoważne przez pełny reload strony przy każdej nawigacji.
