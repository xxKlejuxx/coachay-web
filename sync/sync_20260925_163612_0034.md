## 7. ⚠️ BŁĄD + nowy model dat eventu — decyzje: a) serwer, b) od 00:01, c) tak

**Błąd:** formularz eventu ma pole **„Przypomnienie (dni przed)”** (domyślnie 7, zakres 1–30), zapisywane jako **`events.reminderDays`**. **Nikt go nie czyta.** Web, serwer i (wg #0024) appka szukają `events.reminderHoursBefore`, którego w eventach nie ma, więc zawsze biorą domyślne **48 h**. Ustawienie trenera jest ignorowane.

**Nowy model (pomysł Rafała):** event ma gotowe daty, nikt niczego nie przelicza w locie:

| Pole | Typ | Znaczenie | Wyliczenie |
|---|---|---|---|
| `date` + `timeFrom` | string | kiedy się odbywa (czas PL) | bez zmian |
| **`startAt`** | Timestamp | to samo jako czas | `date`+`timeFrom` w Europe/Warsaw |
| `createdAt` | | kiedy utworzono | bez zmian |
| **`displayFrom`** | Timestamp | od kiedy widoczny dla rodzica/zawodnika | **00:01 (PL) dnia `date − reminderDays`** |
| **`reminderAt`** | Timestamp / null | kiedy cichy push `EVENT_REMINDER` | `startAt − clubs.reminderHoursBefore` h; **null** gdy klub ma 0 (wyłączone) |

Decyzje:
- **a)** pola wylicza **serwer** (trigger na zapis eventu), niezależnie od tego, czy zapisał web, czy appka; web i appka **tylko czytają**; jednorazowe uzupełnienie istniejących eventów;
- **b)** `displayFrom` = **00:01** czasu PL dnia „data eventu − `reminderDays`” (brak `reminderDays` → 7); jedyna granica czasowa to północ;
- **c)** zmiana `clubs.reminderHoursBefore` → serwer przelicza `reminderAt` we **wszystkich przyszłych** eventach klubu.

**Reguła widoczności (web, appka, licznik — identycznie):** event widoczny, gdy `displayFrom <= teraz` **i** `date >= dziś (PL)` **i** `status` nie jest `CANCELLED`/`DELETE`. Pole `events.reminderHoursBefore` i domyślne 48 h znikają.
